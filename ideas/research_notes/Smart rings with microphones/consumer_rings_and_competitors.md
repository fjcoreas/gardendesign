## Which rings have microphones, and what are their specs, price, status and AI stack?

### Takeaway
At least nine microphone rings were on sale, in preorder or announced by Nov 2026: Pebble Index 01, Sandbar Stream, Vocci, Wizpr (VTouch), Aina, Spark Ring, Kunlun Skywork TriRing, Huling (Beijing), plus generic Shenzhen OEM "recording/translation" rings. The Amazon Echo Loop was discontinued in 2020. Mainstream health rings (Oura, Samsung, Ultrahuman, RingConn, Circular) are biometric-only, as far as I found. Most mic rings deliberately skip health sensors and use push-to-talk buttons rather than always-on listening.

## Which rings let users send voice to ChatGPT, Claude or custom agents (SDK, API, webhooks, MCP)?

### Takeaway
Two rings are already open in ways that matter for a "ring to Claude" product. **Pebble Index 01** has an open-source app, webhooks that send raw audio and/or transcripts, and MCP tools. **Vocci** has an MCP server that works with Claude, Claude Code, ChatGPT and Codex. Sandbar has no public API, only a promised Notion export. Wizpr routes to consumer chatbots, but sources disagree on whether Claude is one of them.

### Cited Findings
- **Pebble Index 01:** all the logic lives in the Pebble mobile app, which is open source at github.com/coredevices/mobileapp. There is no ring firmware SDK. — [Pebble Developers: Index 01](https://developer.repebble.com/index-01/)
- **Pebble Index 01:** "You can route all recordings from Index 01 to your own app, server or home lab very easily via Webhooks". You can send the raw audio and/or the text transcription. — [Pebble Developers](https://developer.repebble.com/index-01/)
- **Pebble Index 01:** each automatic action (reminder, note, alarm/timer) is built as an MCP tool. Remote MCP servers are only called by the cloud model. The product page claims MCPs run locally on the device with no cloud server; the dev docs give the cloud-only caveat for remote MCP, so the two disagree. Publishing plugin-dependent apps is reported as currently limited. — [Pebble Developers](https://developer.repebble.com/index-01/); [Product page](https://repebble.com/index?amp=&amp=); [Wearable Index](https://wearableindex.com/devices/pebble-index/)
- **Vocci:** uses MCP to send transcripts, summaries, key moments and action items into ChatGPT or Claude. — [Vocci press release via Yahoo Finance](https://finance.yahoo.com/technology/ai/articles/vocci-ring-now-available-public-130000905.html)

Its docs describe a secure, read-only connection for user-approved context. — [Vocci Connect Your AI](https://vocci.ai/pages/connect-your-ai); [Vocci docs](https://docs.vocci.ai/)

### Inferences
- Pebble's webhook (raw audio or transcript, sent to any URL) is the most direct path today from a ring to a self-hosted Claude agent. A webhook receiver could start a Claude Code job on a GitHub branch with no hardware work. The limit is the battery: about 12–14 h of total recording over the ring's life, which suits short commands, not dictation.
- Vocci's MCP integration is pull-based and read-only. Claude can read what the ring captured, but the ring cannot push a voice command that starts an agent action. That makes it a context source, not a command interface.
- None of the rings found offers a first-class "voice command → coding agent → branch/PR" flow. The "agent" features in Aina and Pebble target consumer tasks (reminders, Uber, notes).

### Gaps
- I could not confirm whether Sandbar, Aina, Spark or Huling offer any webhooks or API. Their developer pages could not be fetched, and searches returned none.
- I could not confirm whether Pebble's cloud model is Claude or another vendor's.
- I found no ring that integrates natively with Claude Code beyond Vocci's MCP connection and a Pebble webhook you build yourself.

## What gaps could a "ring → Claude Code agent on a GitHub branch" product fill?

### Takeaway
No ring found turns a spoken command into a developer-agent action (code change, branch, PR). The existing integrations either send transcripts out (Pebble webhook) or expose recordings for an LLM to read (Vocci MCP). A thin, open "ring → webhook → Claude Code" bridge, plus feedback on the ring itself, is unclaimed territory.

### Cited Findings
- Pebble already sends raw audio and transcripts to any webhook, and its app is open source. That makes a hardware-free prototype possible. — [Pebble Developers](https://developer.repebble.com/index-01/)
- Vocci's Claude Code integration is read-only, and Claude uses it only when you name Vocci. — [note.com review](https://note.com/uemin1959/n/n004db8b24445?hl=en); [Vocci docs](https://docs.vocci.ai/)
- Aina, the only ring with a screen and speaker (useful for confirming or approving agent actions), targets consumer agents. It ships Jan 2027 and works with iPhone and Mac only. — [TechCrunch](https://techcrunch.com/2026/11/05/ainas-smart-ring-has-a-screen-a-joystick-and-a-mic-so-you-can-talk-to-ai-agents/); [Whalesbook](https://www.whalesbook.com/news/English/technology/Bengaluru-Startup-Aina-Launches-dollar399-AI-Ring-for-Jan-2027/6aecca944fc30694db5fcc5e)
- Sandbar markets an "agentic world" interface but has no public API, only a planned Notion export. — [PR Newswire](https://www.prnewswire.com/news-releases/sandbar-raises-23m-to-build-a-wearable-conversational-interface-for-an-agentic-world-302709556.html); [TechCrunch](https://techcrunch.com/2025/11/05/former-meta-employees-launch-stream-a-smart-ring-that-takes-voice-notes-and-controls-music/)
- Omi shows that an open developer ecosystem (webhooks, REST API, app store) can attract a community of 250+ apps, but it is a pendant, not a ring. — [TechCrunch](https://techcrunch.com/2025/01/08/omi-a-competitor-to-friend-wants-to-boost-your-productivity-using-ai-and-a-brain-interface); [Omi docs](https://docs.omi.me/)

### Inferences
- **Gap 1, push rather than pull to agents:** no ring sends a command that starts a Claude Code session or GitHub Action. A webhook-to-agent bridge that works with any ring (starting with Pebble, which supports it now) could be the product, without any hardware.
- **Gap 2, closing the loop:** almost no ring returns agent status to the wearer. Pebble has an RGB LED; Aina has a screen and speaker. Confirming "PR opened / tests failed" with a haptic pulse, LED or watch notification is unaddressed.
- **Gap 3, developer-grade openness on a ring:** only Pebble's app is open. No ring offers an open firmware SDK or a BLE audio stream spec comparable to Omi's.
- **Gap 4, bring your own LLM:** Sandbar and Vocci bundle their own AI subscriptions. Routing to the user's own Claude account or API key, with MCP and Claude Code in the loop, avoids a second subscription.
- **Gap 5, safety for irreversible actions:** voice-triggered code changes need confirmation steps (dry run, then approve), and a branch-only policy fits this well. No competitor addresses it.
- **Risks:** Pebble's non-rechargeable battery limits heavy use. Vocci could add write or push tools to its MCP. Aina and Sandbar are well funded and explicitly "agentic" and could move into developer workflows.
