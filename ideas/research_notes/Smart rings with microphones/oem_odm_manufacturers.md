## Q1. Which manufacturers offer smart rings with a microphone (or can add one)?

### Takeaway
Mic-equipped rings exist at two very different tiers: (a) cheap Shenzhen "AI voice recording / transcription" rings sold on Global Sources / Made-in-China / Alibaba as OEM/ODM (some also claim health tracking), and (b) higher-end reference designs/ODM platforms such as Goertek's Comma 2 Listener (mic + PPG/SpO2 + temperature + IMU), which is the closest match to the full requested sensor set. The popular hackable health rings (Colmi R02/R06/R10/R12) do **not** have a microphone.

## Q2. Typical MOQ, unit price at 500 / 1k / 10k, NRE, and lead time (custom design vs existing private-label)

### Takeaway
Private label of an existing model: MOQ ~200–3,000 units, listing prices ~US$19–60/unit for mic rings (some ~US$108–118 for premium finishes). Full custom ODM: MOQ ~1,500–2,000+ (some sources say 5,000–10,000), and NRE ranges from ~US$5–20k (molds/firmware tweaks) to US$150–500k (fully new hardware). Lead times: samples days–weeks; production 15–35 days for existing models up to 6–12 months for new designs. No 10k-unit price points were found.

## Q3. SDKs, BLE protocol docs, custom firmware, and audio routing to a custom app

### Takeaway
Mid-tier Chinese ODMs (e.g., J-Style) advertise native iOS/Android/Flutter SDKs to qualified partners; mic-ring SDK terms are rarely documented. The Colmi R02/R06/R10 family has a well-documented reverse-engineered BLE protocol and even custom firmware, but no mic. Pebble Index 01 publishes developer docs for its audio ring. Streaming audio over BLE GATT works but has latency/bandwidth constraints; LE Audio (LC3) on chips like nRF5340 is the cleaner route.

### Cited Findings
**Vendor SDKs**
- J-Style: native iOS (Swift/Obj-C), Android (Kotlin/Java), Flutter SDK, RESTful Cloud API and webhooks; docs at jointcorp.com/sdk-api — [J-Style SDK & API guide](https://www.jointcorp.com/smart-ring-and-fitness-band-sdk-api-a-developers-guide/); SDK/API available to qualified ODM/OEM partners without mandatory subscription fee as of 24 Mar 2026 (stated in an ECG-band post) — [J-Style ECG band guide](https://www.jointcorp.com/ecg-smart-band-manufacturer-how-to-choose-the-right-odm-oem-partner/)
- Golden Weald lists firmware and APP customization — [Golden Weald](https://www.goldenweald.com/service/ai-smart-ring-oem-odm-manufacturer-ai-recording-translation-wearable-devices/)
- Some ODMs restrict firmware changes because modifications can void existing FCC/CE certifications — [Alibaba smart watch CE/FCC/RoHS guide 2026](https://seller.alibaba.com/blogs/2026/southeast-asia/consumer-electronics/smart-watch-ce-fcc-rohs-certification-guide-alibaba-b2b)

**Open / reverse-engineered rings (Colmi family)**
- colmi_r02_client (tahnok): Python client for stock firmware, with protocol notes; on PyPI — [GitHub](https://github.com/tahnok/colmi_r02_client); [PyPI](https://pypi.org/project/colmi-r02-client/); [Hackaday 2025](https://hackaday.com/2025/03/04/cheap-hackable-smart-ring-gets-a-command-line-client)

- ATC_RF03_Ring (atc1441): findings and **custom firmware** for Colmi R02 and similar rings with BlueX RF03 SoC (200 KB RAM, 512 KB flash) — [GitHub](https://github.com/atc1441/ATC_RF03_Ring); original Hackaday coverage — [Hackaday 2024](https://hackaday.com/2024/06/16/new-part-day-a-hackable-smart-ring)
- Edge Impulse uses a modded firmware (R02_3.00.06_FasterRawValuesMOD.bin) for faster raw sensor streaming, flashed via ATC_RF03 Firmware Writer — [Edge Impulse example](https://github.com/edgeimpulse/example-data-collection-colmi-r02)
- colmi_r0x_controller uses accelerometer taps/scrolls for UI; warns some R02 units ship with other SoCs and are incompatible — [GitHub mirror](https://github.aipraa306.workers.dev/CitizenOneX/colmi_r0x_controller)
- Protocol resembles Nordic UART-over-BLE service — [smittytone blog](https://blog.smittytone.net/2025/04/09/hoard-of-the-rings-colmi/)
- Gadgetbridge supports Colmi R10/R12 and related Yawell models — [Gadgetbridge Yawell](https://gadgetbridge.org/gadgets/rings/yawell/)
- Hugging Face "Halo" open-source health tracking uses these wearables — [Hugging Face blog](https://huggingface.co/blog/cyrilzakka/halo-introduction); Tedium calls R02 a "hacker ring" — [Tedium](https://tedium.co/2024/11/08/colmi-r02-hacker-ring-review/)

**Audio-ring developer docs**
- Pebble Index 01 developer page: firmware detects button presses, records while held, stores until phone collects, transfers over BLE, and broadcasts a BLE advertising packet on press/release — [Pebble Developers Index 01](https://developer.repebble.com/index-01/)

**Audio over BLE technical constraints**
- nRF5340 has I2S and PDM digital mic interfaces; supports LE Audio isochronous channels and LC3 — [nRF5340 spec](https://www.tme.eu/Document/3e794294564952202d03e12371eb0e0e/NRF5340-CLAA-R7-DTE.pdf); [LinkedIn BLE Audio over nRF5340](https://www.linkedin.com/pulse/ble-audio-over-nrf5340-richard-winter)
- Developer reports ~1 s latency streaming live I2S mic audio over BLE GATT on nRF5340, considering LE Audio isochronous channels instead — [Nordic DevZone](https://devzone.nordicsemi.com/f/nordic-q-a/129091/nrf5340-live-i2s-microphone-audio-streaming-over-ble-with-low-latency)

### Inferences
- For routing audio to a custom app, require in the contract: (1) documented BLE GATT service/characteristics for audio (or source code), (2) codec spec (Opus/ADPCM/LC3, sample rate), (3) buffered "record then sync" mode (like Pebble) since continuous streaming hurts ring battery, (4) right to ship your own firmware builds, and (5) re-certification plan if firmware changes radio behavior.
- The Colmi ecosystem is useful for prototyping health/IMU features cheaply, but cannot provide voice capture; a mic would require a different platform.

### Gaps
- No public SDK documentation found for any mic-ring ODM (eIoT, Xinrui, Lanke, MCL, Golden Weald).
- Whether Pebble Index 01 firmware is open-source (Core Devices open-sourced PebbleOS previously) was not confirmed.

## Q5. Risks: IP, quality, battery certification (UN38.3), sizing kits, warranty, certifications

### Takeaway
Key risks: certifications don't transfer automatically to a rebranded product, firmware changes can void FCC/CE, UN38.3 must match the exact cell, and listing claims are self-reported. Sizing-kit and IP-protection specifics were not found.

### Cited Findings
- CE, FCC, RoHS described as core market-access certifications for smart rings; ISO 9001 optional — [Alibaba seller blog ISO9001/ASTM smart rings](https://seller.alibaba.com/blogs/2026/southeast-asia/smart-rings/iso9001-astm-certification-guide-alibaba-b2b)

- UN38.3 test reports required for air and sea shipping of lithium batteries; verify report matches the production cell — [ZRLK Lab](https://www.zrlklab.com/en/show-100-3614.html); [Import compliance guide](https://wanpup.pages.dev/blog/importing-jump-starters-usa-fcc-cpsc-requirements.html)

### Inferences
- A ring with always-available mic adds privacy/legal exposure (recording-consent laws, GDPR voice data) beyond normal wearable risk; health claims (SpO2) may trigger medical-device rules if marketed clinically (cf. Movano's FDA 510(k) path).
- BOM substitution (seen in Colmi) is a quality risk: lock BOM (SoC, mic, PPG, cell) in the contract and require golden-sample approval.
